# サイン入り動画 仕様書（MVP / デモフェーズ）

## 1. 背景・要望

事前撮影した動画にアーティストの手書きサインと宛名（ニックネーム）を入れて
購入者に届けたい。Perfumeライブの会場限定ARフォトフレームの動画版イメージ。

## 2. 要望の階層

| レベル | 概要 | 技術難易度 |
|---|---|---|
| A | ライブ配信中にアーティストがリアルタイム書き込み | ★★★★ |
| B-2 | 事前収録動画を購入者ごとに個別用意 | ★★★ |
| B-1 | 共通動画+ブラウザ内フレーム合成 | ★ |
| B-3 | 共通動画+個別サインPNG+宛名テキスト | ★★ |

**今回着手するスコープ**：B-2 を目指す前段として、まずブラウザ完結の**サイン入り動画 デモ**を作る。
将来 S3/R2 インフラ契約後、本番フローに昇格させる。

## 3. デモ仕様（フェーズ1）

### 3-1. 設置場所
- `/admin/signed-video-demo`（社内検証用、サイドバー非表示）
- 既存の `/admin/video-demo` と同じ「ブラウザ完結デモ」枠

### 3-2. 体験フロー

```
1. 動画を用意
   - 動画ファイルをブラウザでアップロード（Blob URL でメモリ保持）
   - or サンプル動画（public/ に同梱）から選択
2. 宛名を入力
   - テキストフィールドにニックネーム
3. サインを描く
   - Canvas 描画ボード（iPad/Pencil 想定の Pointer Events）
   - 色・太さの選択
   - クリア・取り消し
   - 完成後「サインを確定」で PNG 化
4. プレビュー
   - <video> + <canvas> 合成
   - 動画の上に宛名フレーム枠＋テキスト
   - 動画の上に半透明オーバーレイで サイン PNG
5. ダウンロード
   - Canvas.captureStream(30) + MediaRecorder で合成済み動画を書き出し
   - WebM/MP4 形式（iOS Safari は MP4 優先）
   - 写真Appへの保存は Web Share API 経由
6. リセット
   - 全工程をクリアして最初から
```

### 3-3. 動画の入手経路

ブラウザの CORS 制約により、**外部動画URL参照は技術的に不可**：

| 入手経路 | デモで使えるか |
|---|---|
| YouTube/Vimeo URL | ❌ Canvas に取り込めない（iframe 越しは描画不可） |
| 外部 mp4 URL (CORS無し) | ❌ Canvas が tainted 化、合成・保存できず |
| 外部 mp4 URL (CORS設定済み) | ✓ ただし配信側の協力が必要 |
| **public/ 配下のサンプル** | ✓ 同一オリジン、確実に動く |
| **アップロードした Blob URL** | ✓ ブラウザ内データ、確実に動く |

→ **デモではアップロード + サンプル選択の2方式**を用意する。

### 3-4. UI要素

```
[ヘッダー]
  サイン入り動画 デモ
[ステップ1: 動画]
  ・[サンプルA] [サンプルB] [サンプルC] ボタン
  ・もしくは [ファイルを選択] ボタン
  ・選択中の動画プレビュー
[ステップ2: 宛名]
  ・宛名入力欄（最大10文字想定）
  ・フレーム色選択（ピンク/ゴールド/ネオン など、既存video-demoのフレーム流用）
[ステップ3: サイン]
  ・Canvas 描画ボード（横長、タブレット最適サイズ）
  ・色選択（黒/白/赤/金）
  ・線の太さスライダー
  ・[元に戻す] [全消去] [サインを確定]
[ステップ4: プレビュー&保存]
  ・合成プレビュー（video + canvas）
  ・[ダウンロード] [共有/アルバムに保存] [最初からやり直す]
[注意書き]
  ・サーバーには何も保存されません
  ・動画と合成画像はこのブラウザ内のみで処理されます
```

### 3-5. 技術スタック（フェーズ1）

- Next.js 15 App Router の Client Component
- `<video>` + `<canvas>` で合成
- `getUserMedia` 不要（カメラ起動なし）
- Pointer Events API（iPad Pencil + 圧力対応）
- MediaRecorder API（書き出し）
- Web Share API（写真Appへの保存）
- ストレージ操作なし（純粋なブラウザ完結）

## 4. 本番化フェーズ（インフラ契約後）

### 4-1. 新規データモデル（案）

```prisma
// DigitalContent.type に新しい列挙値を追加
enum DigitalContentType {
  PHOTO        // 既存
  AUDIO        // 既存
  VIDEO        // 既存
  SIGNED_VIDEO // 新規: サイン入り動画
}

// 既存 DigitalDelivery を拡張
model DigitalDelivery {
  // ... 既存フィールド ...
  // 新規:
  baseVideoUrl     String?   // ベース動画URL (S3)
  signedVideoUrl   String?   // 合成済み動画URL (S3)
  signaturePngUrl  String?   // サインPNG (S3 or DB)
  recipientName    String?   // 宛名
  frameVariant     String?   // フレーム種別
}
```

### 4-2. 本番フロー

```
[アーティスト管理画面]
  1. ベース動画をアップロード（S3）
     → 全員共通動画 or 購入者ごとに別動画
  2. 購入者一覧から「次の人」を選択
  3. サイン描画ボードで宛名・サインを描く
  4. 「合成して保存」
     → サーバー側で ffmpeg 等で合成（or クライアントで合成→アップロード）
     → 合成済み動画を S3 へ
     → DigitalDelivery.status を READY に
[購入者マイページ]
  1. 注文済みのサイン動画一覧
  2. 視聴ページ（HLS / mp4 ストリーミング）
  3. ダウンロード（署名付きURL）
```

### 4-3. インフラ要件

| 要素 | 候補 |
|---|---|
| 動画ストレージ | Cloudflare R2 / AWS S3 / Vercel Blob |
| 動画配信 | 上記の署名付きURL or CloudFront / Cloudflare CDN |
| 動画変換 | サーバー側 ffmpeg（コンテナ）or クライアント書き出し |
| 大容量アップロード | Multipart upload（S3 直接 PUT、署名URLでクライアントから） |

## 5. 「サインを動かす」拡張余地

将来的に「サインが書かれていくアニメーション」を実装する場合の技術選択肢：

| 方式 | 仕組み | 出力 |
|---|---|---|
| ① 一発撮り | 録画中にアーティストが書く | 動画ファイルそのまま |
| ② サーバー側合成 | ベース動画 + 透明サイン動画 を ffmpeg で合成 | 合成済み動画 |
| ③ ブラウザ再生時重ね | 動画 + サイン時系列JSON を Canvas で再生時に合成 | 視聴のみリッチ、DL は別合成必要 |
| ④ 静止サイン+宛名フレーム | 静止 PNG + テキストを重ねるだけ | 軽量、合成も簡単 |

**フェーズ1は ④** を採用。アニメ化が必要になったら ② か ③ を追加で検討。

## 7. 既知の技術的制約

- **iPad Safari**: WebM 録画不可。MP4 優先。
- **PCブラウザ**: MediaRecorder で MP4 出力できないケースあり。WebM フォールバック。
- **動画長**: 5分以内推奨。それ以上はメモリと録画時間がボトルネック化。
- **解像度**: 1080p（1920x1080）でメモリ約 1.2GB（30fps × 5分）。720p 推奨。
- **iOS Safari**: 自動再生は muted 必須。getUserMedia は HTTPS + ユーザー操作起因のみ。
