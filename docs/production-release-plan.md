# 本番リリース Phase 1 計画

**作成日:** 2026-07-10
**対象読者:** 実装者、レビュワー、ステークホルダー
**ステータス:** ドラフト → 合意後にIssue分解して実装開始

## 0. TL;DR

- **Phase 1 のゴール**: オンラインイベント（グッズ販売 + タレントのその場サイン → 即配信）を運用できる状態
- **後回し**: 写真集サイン / アベリアくじ / トレカ
- **サイト名**: 未定（コード上は暫定で avelia-funclub のまま）
- **メール**: **Resend** を採用
- **オンラインイベントフロー**: タレントは配信でファンにあいさつしつつ、事前に受け取ったサイン依頼を1件ずつ処理していく。「完了」ボタンを押すと当該ファンに即メール送信 + マイページに反映

## 1. 商品モデルの整理

### 1.1 商品種別

現在の `Product.type` は `PHYSICAL | DIGITAL` の2値。Phase 1 では以下 3 種別に細分化する。

| 種別 (仕様) | Prisma 表現 | 納品方式 | 例 |
|---|---|---|---|
| **物品** | `type = PHYSICAL` | 配送（社内出荷 / 倉庫出荷） | ポストカード、CD、写真集本など |
| **デジタル写真サイン** | `type = DIGITAL` + `DigitalContent.deliveryType = PERSONALIZED` + 画像用オプション | オンラインイベントでタレントがサイン → 即メール配信 | サイン入り2ショット写真 |
| **デジタル動画サイン** | `type = DIGITAL` + `DigitalContent.deliveryType = PERSONALIZED` + 動画用オプション | 同上（動画） | 短尺コメント動画 |

Product 側で「デジタル写真サイン」「デジタル動画サイン」を明示的に選べる UI を用意し、内部的には既存の DigitalContent モデルにマッピングする。**スキーマは大きく壊さず、`DigitalContent.type` (`IMAGE | FILE`) を活用 or 拡張する**。

### 1.2 商品作成 UI の変更

管理画面の商品作成フォームで「種別」を3択ドロップダウンにする:

- 物品（配送あり）
- デジタル写真サイン（オンラインでその場サイン）
- デジタル動画サイン（オンラインでその場サイン）

種別に応じて表示するフィールドを切り替える:

- 物品 → 発送元（IN_HOUSE / WAREHOUSE）、配送予定日
- デジタル写真サイン → サイン用ベース画像（写真の原本）
- デジタル動画サイン → サイン合成対象の動画（原本）

### 1.3 動画サインの実現方式（確定: リアルタイム描画型）

タレントは動画をプレイヤーで再生しながら、オーバーレイキャンバスに直接ペンでサインを描く。描画データは動画のタイムラインに紐づけて保存し、再生時に合成する（サーバー再エンコード不要）。

- **技術要素**: Canvas + Pointer Events（既存 `Signature` 実装と同じ）
- **保存フォーマット**: サインパス (`[{x, y, t, pressure}]`) を JSON で持ち、動画URLと組で保存
- **再生**: フロント側で `<video>` + `<canvas>` オーバーレイ再生。時間軸に沿ってパスを再描画
- **代替: 焼き込み動画も選択可能**: 将来的に「サイン焼き込み済みの mp4 を書き出す」機能を追加してもよい（今は不要）

## 2. オンラインイベントの実施フロー

### 2.1 事前準備（管理者）

1. イベント作成
2. 商品作成（種別・価格・在庫）
3. 配信URL（YouTube Live など）を設定
4. ニックネーム記入項目の準備

### 2.2 販売期間中（ファン）

1. イベントページで商品を選択
2. 買う数量分だけニックネーム・宛名を入力
3. Stripe で決済
4. 決済成功 → `Order.status = PAID`、`DigitalDelivery` レコードが `PENDING` で自動作成される
5. 注文確認メールが届く

### 2.3 イベント当日（タレント）

1. タレントは配信でファンに向けてトーク開始
2. 管理画面「サインセッション」を開く
3. 全 `DigitalDelivery(status=PENDING)` が一覧表示される
4. 1件ずつ処理:
   - ファンの宛名・ニックネームを確認
   - 原本の上にサインを描く（既存の `Signature` テーブルに保存）
   - **「完了」ボタンを押す** → `DigitalDelivery.status = READY` + サイン付き画像/動画を生成 + Blob 保存
5. 完了と同時にファンにメール送信 + マイページで閲覧可能に

### 2.4 イベント終了後

- 未完了の `DigitalDelivery` があれば管理者に通知
- タレントが後日書き足すことも可能

### 2.5 決めきれていないこと

- [ ] **サイン進捗の可視化**: ファンから「あと何番目」が見えるようにするか
- [ ] **タレント側UIの端末**: タブレット + Apple Pencil 前提でよいか（Pointer Events 対応）
- [ ] **配信プラットフォーム**: YouTube Live 想定でよいか（既存の `streamingUrl` フィールドがそのまま使える）

## 3. メール送信基盤

### 3.1 選定: Resend

理由:
- Vercel との相性が良い（`RESEND_API_KEY` 1 個で完結）
- `.env.example` に既に枠がある
- 小規模スタートでは無料枠内、規模拡大時のスケールも問題なし
- DKIM/DMARC の設定が管理画面ベース

### 3.2 送信するメール一覧（Phase 1）

| # | 種類 | トリガー | 内容 | 優先度 |
|---|---|---|---|---|
| 1 | 会員登録の確認 | サインアップ | 認証リンク | 高 |
| 2 | パスワードリセット | リセット申請 | リセットリンク | 高 |
| 3 | 注文確認 | 決済成功 (Stripe webhook) | 注文明細・領収情報 | 高 |
| 4 | サイン完了 | タレントが「完了」を押した瞬間 | 即配信URL付き | **最重要** |
| 5 | 発送完了 (物品) | 管理者が発送完了処理 | 追跡番号URL付き | 高 |
| 6 | 決済失敗 | Stripe webhook (failed) | 再決済リンク | 中 |
| 7 | イベントキャンセル・代金返還 | 管理者操作 | 詫び + 返金完了通知 | 中 |
| 8 | イベントリマインダー | Vercel Cron | 開催日前日 / 数時間前 | 中 |

### 3.3 メールテンプレ

- React Email を使う（Resend との相性が良い）
- 共通ヘッダー/フッターを持つ簡素なテンプレ

### 3.4 決めきれていないこと

- [ ] **送信元ドメイン**: 独自ドメイン取得次第
- [ ] **From アドレス**: `no-reply@<domain>` で統一するか、`support@` を使うか
- [ ] **本文のタイトル/文面テンプレ**: 別途詳細設計
- [ ] **メール開封計測**: Resend のトラッキングを使うか

## 4. 認証拡張 (Auth.js)

### 4.1 現状

- 一般ユーザー: Email + Password（Auth.js）
- 管理者: 別モデル（Admin テーブル）でロール分離

### 4.2 追加する機能

- **メール確認フロー**: 新規登録時、`emailVerified` になるまで一部機能を制限
- **パスワードリセット**: リセットトークン発行 → メールで送信 → リセット完了

### 4.3 想定スキーマ変更

- `User.emailVerified DateTime?`（Auth.js の標準フィールドを活用）
- `EmailVerificationToken` テーブル（token, userId, expiresAt）
- `PasswordResetToken` テーブル（token, userId, expiresAt）

---

## 5. スキーマ変更まとめ

| モデル | 変更 | 理由 |
|---|---|---|
| `User` | `emailVerified DateTime?` 追加 | メール確認フロー |
| `EmailVerificationToken` | 新設 | メール確認 |
| `PasswordResetToken` | 新設 | リセット |
| `Product` | `productKind` 追加（`PHYSICAL / DIGITAL_PHOTO_SIGN / DIGITAL_VIDEO_SIGN`） | 3種別を明示 |
| `Event` | 特に変更なし（`streamingUrl` を活用） | - |

**マイグレーションは1個にまとめる** or **段階的に**するかは実装時に判断。
